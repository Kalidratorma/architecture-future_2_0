# Task2 (DFD и аргументация разделения на домены)

## Цель
Разделить архитектуру данных компании Future 2.0 на домены и показать потоки данных. Это позволит уйти от монолитного DWH и перейти к data mesh-подходу, где каждая команда отвечает за свой «data product».

---

## DFD Level 0 (As-Is → To-Be переход)
На верхнем уровне система представлена как **P0: Data Management Platform**.
- Вход: потоки данных из внешних систем (Fintech, Clinics, Pharma, Med Electronics).
- Обработка: единый процесс управления данными.
- Выход: три основных хранилища/сервиса — Data Platform (Lakehouse), Legacy DWH и Self-Service Portal.

См. диаграмму в [`dfd.drawio`](./dfd.drawio), страница **DFD Level 0**.

---

## DFD Level 1 (декомпозиция P0)
На уровне декомпозиции платформа разделяется на 5 процессов по доменам:

- **P1: Finance Data Processing**  
  Источники: банковские транзакции, кредиты, счета.  
  Продукты: витрины с финансовыми KPI, отчёты для финтеха.

- **P2: Clinics Data Processing**  
  Источники: HIS/регистратура, расписания, услуги.  
  Продукты: агрегаты загрузки врачей, обезличенные данные для аналитики.  
  PHI (медкарты, исследования) не попадают в витрину.

- **P3: Pharma Data Processing**  
  Источники: склады, продажи, заказы.  
  Продукты: витрины для управления цепочками поставок и запасами.

- **P4: Med-Electronics Data Processing**  
  Источники: телеметрия медоборудования.  
  Продукты: показатели SLA, предиктивное обслуживание.

- **P5: AI/ML Data Processing**  
  Источники: разрешённые доменные наборы.  
  Продукты: модели/фичи для ИИ-сервисов.

Все процессы пишут в **D1: Lakehouse** (Raw/Curated/Serving).  
Из Lakehouse формируются **Data Products (D2–D5)** для каждого домена, которые поступают в **D6: Semantic Layer & Portal**.

См. диаграмму в [`dfd.drawio`](./dfd.drawio), страница **DFD Level 1**.

## Преимущества разделения на домены

1. **Независимость развития**  
   Каждая доменная команда управляет своими пайплайнами и витринами, без правок в общем DWH.

2. **Снижение регуляторных рисков**  
   Данные PHI/PII остаются в доменах, в витрину попадают только безопасные агрегаты.

3. **Time-to-Market**  
   Новый отчёт строится внутри домена, без глобальных доработок.

4. **Прозрачность и повторное использование**  
   Все датасеты зарегистрированы в каталоге, доступны через портал и имеют lineage.

5. **Постепенный отказ от легаси**  
   Legacy DWH сохраняется как отдельное хранилище, критичные отчёты поддерживаются до полной миграции.
